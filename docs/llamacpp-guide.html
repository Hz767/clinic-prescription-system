llama.cpp 实战指南

零门槛本地部署大模型 · 从安装到生产级 API 服务

一、llama.cpp 是什么？

llama.cpp 是由 Georgi Gerganov 用纯 C/C++ 编写的 LLM 推理引擎，是 Ollama 的底层核心。它的核心贡献是 GGUF 量化格式——将 70B 模型压缩到 40GB 以内，让普通笔记本也能跑大模型。

极低硬件门槛

4-bit 量化后 Llama-3-8B 仅需 4.9GB 内存，纯 CPU 也能跑。树莓派、老旧笔记本均可运行。

CPU + GPU 混合推理

模型太大放不进显存？llama.cpp 支持将部分层卸载到 CPU，其余保留在 GPU，灵活分配资源。

跨平台 + 零依赖

Windows / macOS / Linux 原生运行，支持 CUDA、Metal、Vulkan、ROCm 多种后端。

OpenAI 兼容 API

llama-server 提供 /v1/chat/completions 端点，可直接替换 OpenAI 客户端。

二、安装（Windows）

1

下载预编译二进制（推荐，最快）

前往 GitHub Releases，下载 llama-bxxxx-win-x64.zip（带 CUDA 支持则选 llama-bxxxx-win-x64-cuda.zip）。

解压到 D:\llama.cpp，无需安装。

2

从源码编译（需要 CUDA 加速时推荐）

需要安装：Visual Studio 2022（勾选"使用 C++ 的桌面开发"）+ CMake。

# 克隆仓库
git clone https://github.com/ggml-org/llama.cpp
cd llama.cpp

# CMake 配置（CUDA 加速）
cmake -B build -DGGML_CUDA=ON
cmake --build build --config Release -j

# 编译产物在 build/bin/Release/ 目录
3

下载 GGUF 模型

从 Hugging Face GGUF 搜索下载。推荐模型：

模型量化大小说明
Qwen2.5-7B-InstructQ4_K_M~4.7GB中文能力强，推荐首选
Llama-3.1-8B-InstructQ4_K_M~4.9GB英文最佳，通用场景
DeepSeek-R1-Distill-Qwen-7BQ4_K_M~4.7GB推理能力强，思维链
Qwen2.5-14B-InstructQ4_K_M~8.7GB16GB 内存即可运行
量化级别说明：Q4_K_M 是性价比最高的选择——体积小、精度损失极低。Q8_0 精度最高但体积翻倍。Q2_K 最小但质量下降明显。

三、命令行使用（llama-cli）

3.1 最简启动

# 交互式聊天
llama-cli -m models\qwen2.5-7b-instruct-q4_k_m.gguf -c 4096 --color -i

3.2 单次推理

# 一次性问答
llama-cli -m models\qwen2.5-7b-instruct-q4_k_m.gguf \
  -p "用一句话解释什么是量子计算" \
  -n 256 \
  --temp 0.7

四、Server 模式 — OpenAI 兼容 API

这是 llama.cpp 最强大的功能，提供与 OpenAI /v1/chat/completions 完全兼容的 HTTP API。

4.1 启动服务

# 基础启动（CPU 推理）
llama-server -m models\qwen2.5-7b-instruct-q4_k_m.gguf

# 生产级启动（GPU 加速 + 大上下文）
llama-server -m models\qwen2.5-7b-instruct-q4_k_m.gguf \
  --host 0.0.0.0 \
  --port 8080 \
  --ctx-size 8192 \
  --n-gpu-layers 35 \
  --threads 8 \
  --batch-size 512
启动后访问：浏览器打开 http://localhost:8080 即可看到内置 Web 聊天界面。API 文档在 http://localhost:8080/docs。

4.2 API 调用

# Chat Completion（OpenAI 兼容）
curl -X POST http://localhost:8080/v1/chat/completions \
  -H "Content-Type: application/json" \
  -d '{
    "model": "gpt-3.5-turbo",
    "messages": [
      {"role": "user", "content": "你好，用中文介绍你自己"}
    ],
    "temperature": 0.7,
    "max_tokens": 512
  }'

# Python 调用（直接使用 openai 库）
from openai import OpenAI
client = OpenAI(base_url="http://localhost:8080/v1", api_key="not-needed")
response = client.chat.completions.create(
    model="gpt-3.5-turbo",
    messages=[{"role": "user", "content": "用 Python 写一个快速排序"}]
)
print(response.choices[0].message.content)

# C# 调用（你的诊所系统可以直接集成）
using var http = new HttpClient { BaseAddress = new Uri("http://localhost:8080") };
var json = JsonSerializer.Serialize(new {
    model = "gpt-3.5-turbo",
    messages = new[] { new { role = "user", content = "你好" } }
});
var response = await http.PostAsync("/v1/chat/completions",
    new StringContent(json, Encoding.UTF8, "application/json"));
# Embedding（向量化）
curl http://localhost:8080/v1/embeddings \
  -H "Content-Type: application/json" \
  -d '{"input": "Hello world", "model": "gpt-3.5-turbo"}'

五、性能调优

5.1 GPU 层数调优（最关键）

--n-gpu-layers 控制多少层卸载到 GPU。这是影响推理速度的最重要参数。

# 小模型（8B），8GB 显存：全部放 GPU
llama-server -m model.gguf --n-gpu-layers 99

# 大模型（70B），24GB 显存：部分放 GPU
llama-server -m model.gguf --n-gpu-layers 35

# 纯 CPU 推理（无 GPU）
llama-server -m model.gguf --n-gpu-layers 0 --threads 16
找最优值：从 --n-gpu-layers 99 开始，如果显存不足（OOM），逐次减 10 层直到稳定运行。通常 8B 模型在 8GB 显存上可以全部放 GPU。

5.2 量化级别性能对比

量化8B 模型大小质量损失推理速度推荐场景
Q8_0~8.5GB几乎无损慢精度敏感任务
Q4_K_M~4.9GB极低快通用场景（推荐）
Q4_0~4.6GB低最快低配机器
Q2_K~3.2GB中等极快嵌入式/边缘设备

5.3 上下文大小与内存关系

上下文 --ctx-size 越大，KV Cache 占用内存越多。粗略估算：

# 8B 模型，Q4_K_M 量化
--ctx-size 4096   →  KV Cache ≈ 0.5GB 额外内存
--ctx-size 8192   →  KV Cache ≈ 1.0GB 额外内存
--ctx-size 32768  →  KV Cache ≈ 4.0GB 额外内存
注意：不要盲目追求大上下文。8B 模型对超长文本的理解力有限，4K-8K 上下文通常足够。设置过大会导致 OOM 或推理显著变慢。

六、llama.cpp vs Ollama — 什么时候该用？

场景推荐原因
快速上手、不想折腾Ollama一条命令安装，自动管理模型
追求极致性能llama.cpp直接调优 GPU 层数、线程、批处理
CPU 推理 / 无 GPUllama.cppCPU 优化是 llama.cpp 的核心优势
生产环境 API 服务llama.cppllama-server 更轻量、更可控
多模型管理Ollamaollama pull/push 生态成熟
集成到 C/C++ 应用llama.cpp原生 C API，零依赖
实际建议：两者可以共存。Ollama 底层就是 llama.cpp，你用 OLLAMA_NUM_PARALLEL、OLLAMA_CTX_SIZE 等环境变量调优时，本质上就是在调 llama.cpp 的参数。如果觉得 Ollama 环境变量不够用，直接用 llama.cpp 的 llama-server 替代即可——API 完全兼容，代码不用改。

七、常见问题

Q: 启动后报 "failed to load model"？

检查 -m 路径是否正确，确认文件是 GGUF 格式（不是 safetensors 或 pytorch）。

Q: 显存不足（CUDA OOM）？

减少 --n-gpu-layers 值，或降低 --ctx-size。用 llama-perplexity 工具测试内存占用。

Q: 输出乱码/重复？

调整 --temp（0.6-0.8）、--top-p（0.9）、--repeat-penalty（1.1）。

Q: 如何让 llama-server 开机自启？

# Windows 任务计划程序或 NSSM
nssm install LlamaServer "D:\llama.cpp\llama-server.exe" "-m D:\models\qwen.gguf --host 0.0.0.0 --port 8080"
nssm start LlamaServer

Q: 和 Ollama 的 API 兼容吗？

完全兼容。llama-server 的 /v1/chat/completions 端点与 OpenAI API 格式一致，任何使用 OpenAI SDK 的代码都可以直接指向 llama-server。
